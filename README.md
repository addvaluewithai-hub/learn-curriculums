# Learn Curriculums — ورشة إنتاج المناهج

ابدأ كتابة المنهج والاسكربتات والـstoryboards وإنتاج الصوت والتوقيتات **على مراحل منفصلة يفتح كل واحدة منها الإنسان**، مش تشغيل شامل من أول رسالة.
**المعاينة متاحة في `preview-sdk`** بحزمة المحرك المشتركة وإصدار مثبت، منفصلة عن أدوات الإنتاج.
لا حسابات، لا قاعدة بيانات، لا حفظ طالب، ولا نشر تلقائي من هنا.

## Workflow: مرحلة واحدة ثم توقف

لو المستخدم بعت PDF وقال «عايزين نبدأ إنتاج منهج»، اقرأ [بوابات المراحل البشرية](instructions/stage-gates.md). **Stage 00 فقط**: جرد المصدر وحالة حقوقه، تأمين مرجع دائم إذا كان متاحًا ومسموحًا، تخطيط المنهج كله بصورة مبدئية إلى Blocks واختيار B01، وحفظ Source Manifest وCoverage وSTATUS على Draft PR، ثم **STOP من غير كتابة دروس**.

- أول **next / كمل**: Stage 01 — شرح كامل متصل للدروس المبدئية داخل **B01 فقط**، ثم توقف.
- ثاني **next**: Stage 02 — Critique وتصحيح شرح B01، ثم توقف.
- ثالث **next**: Stage 03 — تثبيت حدود الدروس وصياغتها النهائية، ثم توقف.
- رابع **next**: Stage 04 — Scenes وStoryboards وفحوص script، ثم توقف.
- **next block** بعد Stage 04 وبموافقة الإنسان: B02 Stage 01، حتى لو صوت B01 متأجل.
- **next** العادية بعد Stage 04: Stage 05 تجهيز عينة صوت dry-run؛ لا TTS مدفوع ولا نشر تلقائي.
- لو المستخدم علّق أو طلب تصحيحًا: عدّل المرحلة الحالية ثم توقف من غير ما تتقدم. لو طلب عدة مراحل **صراحةً** اتبع النطاق المأذون والمتطلبات الفعلية.

دي قواعد عامة لأي منهج. ما ترفعش كتب PDF الممسوحة تلقائيًا للريبو العام؛ اتبع [حفظ المصادر](instructions/source-handling.md). [التفاصيل الكاملة وحالة الاستئناف](instructions/stage-gates.md).

## البداية

المطلوب: Python 3.11+ فقط. npm اختصار لأوامر الإنتاج؛ لا يحتاج الإنتاج packages. المعاينة فقط تحتاج Node.js 24 وتثبيت اعتمادياتها. أمر `lesson-new` في المثال التالي يخص Stage 04، مش أول تشغيل لكتاب جديد.
إرسال الصوت يحتاج صلاحية GitHub على gemini-tts؛ gh أو connector مأذون يرسل الـpayload.

```bash
python3 tools/cli.py course-new --id biology-basics --title "أساسيات الأحياء"
python3 tools/cli.py lesson-new --course biology-basics --id bio-cells --order 1 --title "الخلية"
python3 tools/cli.py validate
```

املأ course.json بالمصادر وسياسة اللغة، واعمِل تقسيم **مبدئي قابل للمراجعة** للدروس حسب المصدر والأهداف. لكل درس أو مجموعة دروس متجاورة: اعمل خريطة مفاهيم، واكتب مسودات شرح متصلة من غير فرض مشاهد الإنتاج، وانقدها علميًا وتعليميًا ومن ناحية الحمل المعرفي. **بعد النقد راجع حدود الدروس**: تفضل كما هي، أو تتقسم، أو تندمج، أو تتنظم كأجزاء قصيرة داخل نفس الدرس. لو التقسيم اتغير، اكتب افتتاحيات وخواتيم وأسئلة مناسبة للدروس الجديدة؛ ما تقطعش الاسكربت الطويل ميكانيكيًا.
راجع [تخطيط المنهج](instructions/curriculum-planning.md) و[منهجية التدريس](instructions/teaching.md) و[العقد](instructions/contract.md). ثبّت حدود الدروس والـIDs والمراجع والأهداف في OUTLINE قبل تأليف المشاهد النهائي؛ بعد التقسيم، نصوص المشاهد هي المصدر التشغيلي الوحيد.
فحص `script` بيكشف اكتمال البنية فقط، مش جودة التدريس أو اعتماد العلم. بعد الوصول للمرحلة 04، نصوص المشاهد هي المصدر التشغيلي؛ بلاش نسختين مستقلتين من الكلام.

```bash
npm run validate -- --course biology-basics --lesson bio-cells --stage script
npm run audio:prepare -- --course biology-basics --lesson bio-cells --clip N01 --take t01
```

الأمر الثاني يكتب ملف طلب فقط. استخدم المسار الذي يعيده:

```bash
npm run audio:dispatch -- --job curricula/biology-basics/lessons/bio-cells/jobs/JOB_ID.json
```

ده dry-run. إضافة --send تبدأ طلبًا مدفوعًا بعد مراجعة الـpilot وسياسة الفريق.
راجع [الصوت والاستلام](instructions/audio.md)؛ لا تعيد نفس الطلب لأنه ما زال queued.

## التنظيم والملكية

| المسار | المسؤولية | صاحبه |
|---|---|---|
| curricula | كل منهج ومصادره ودروسه ومكوناته | فريق المنهج |
| instructions | الشرح والبورد والصوت والعقد والتسليم | مسؤول طريقة الإنتاج |
| .agents/skills | Skill واحدة تقرأ التعليمات | مسؤول طريقة الإنتاج |
| tools | إنشاء وفحص وصوت وتصدير | مسؤول أدوات الإنتاج |
| preview-sdk | معاينة مستقلة بالمحرك المشترك المثبت | مسؤول المحرّك |
| tests | اختبارات الأدوات وحالات الفشل | مسؤول الأدوات |
| dist | حزم تسليم مولدة لا تعدل يدويًا | أدوات الإنتاج |

لا مناهج حقيقية نُسخت من Learn في هذه الدفعة، ولا أمثلة وهمية داخل الفهرس الحقيقي.
يتكرر نفس تنظيم الدرس: metadata، scenes، media، jobs، review وSTATUS؛ لا أسماء دروس داخل الأدوات.
التسجيلات والأصول تبقى تحت الدرس الذي يملكها.

## بداية العمل مع الـAI

> اقرأ AGENTS.md وSkill produce-learn-lesson و[stage-gates.md](instructions/stage-gates.md) و[source-handling.md](instructions/source-handling.md). عند بدء منهج جديد نفّذ Stage 00 فقط: جرد الملفات والصفحات المتاحة، راعِ حقوق المصدر وتخزينه الآمن، ابنِ Master Outline ومخطط Blocks واختر B01، وسجّل SOURCE_MANIFEST وSOURCE_COVERAGE وSTATUS في Draft PR، ثم توقف بدون دروس. لما أقول next اكتب مسودات كاملة للـBlock الحالي، وبعد كل مرحلة توقف. next block يبدأ الجزء التالي بعد مشاهد الحالي بموافقتي حتى لو الصوت متأجل.

لو أداة AI لا تكتشف Skills تلقائيًا، اقرأ `.agents/skills/produce-learn-lesson/SKILL.md` مباشرة.
لا نفترض أن «3» يعني نفس القانون أو ID في كل منهج.

## مراجعة وتسليم

```bash
npm test
npm run check
npm run validate
npm run export -- --course biology-basics --stage script
```

النتيجة تحت dist/handoff: source كامل وhandoff.json بالملفات والـhashes والمرحلة.
media يفحص التسجيلات، وtimed يفحص كمان anchors المرتبطة بالكلمات.
تأليف التوقيتات خطوة للـAI: يقرأ الاسكربت والمشهد وWord timestamps ويكتب الربط بالمعنى.
راجع [تعليمات التوقيت](instructions/timing.md): لا بوابة تطابق نصي مع ASR ولا موافقة بشرية لكل cue.
الفاحص يتحقق من سلامة الربط والأرقام؛ جودة اختيار الرسم وتوقيته تُراجع في المعاينة.
**دي مش حزمة جاهزة للنشر على الطالب:** تحتاج مراجعة التشغيل الفعلية والتحقق والاستيراد المعتمد.
نجاح tests لا يثبت صحة المحتوى أو النطق. نجاح `validate --stage script` مش اعتماد تربوي أو علمي؛ المراجعات تحتاج أدلة منفصلة.
الشغل الجماعي: branch/PR لكل درس، ومعرف وترتيب متفق عليهما؛ تغييرات الخطة والمصادر لمسؤول المنهج.
CI يفحص تضارب الهويات والترتيب. STATUS القديم ليس قفلًا دائمًا.
الكود اليدوي والتعليمات تحت 300 سطر؛ timestamps/تسجيلات المصنع مخرجات لا تختصر يدويًا لهذا الحد.
